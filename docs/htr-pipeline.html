Manuscript HTR Pipeline

Intake → language/script triage → model routing → recognition → feedback training  ·  engine: kraken · front-end: pycatmus

1 · Routing — one document in, correct model chosen

2 · Training loop — turning corrected pages into a better model

Triage rules (Hermes decides)

  • • Insular minuscule, þ/ð/ƿ, Anglo-Saxon formulae → Track B lane (OE model / interim: OCR Latin only, bounds flagged for human)
  • • Gothic textura/cursiva ≤1500, Lat/Fr/It → CATMuS Medieval (ready)
  • • Secretary & court hand 1500+, wills, registers → McCATMuS (ready; fine-tune = Track A)
  • • Mixed page (Latin charter + OE bounds) → split regions, one lane each, re-stitch output

Ground-truth conventions

  • • Graphematic: transcribe exactly what is inked — ꝑ stays ꝑ, no expansions
  • • NFD Unicode (diacritics/superscripts separate) — matches both base models
  • • Corrections done in pycatmus-app; keep 2–3 pages per batch held out for honest CER
  • • OE side: ASChart / Langscape scholarly editions give text; images via BL IIIF; alignment is the manual cost

Why two models, not one

  • • 500-year script gap: insular vs secretary share almost no glyph shapes
  • • Merged training dilutes priors — each track's errors would get worse
  • • Deployment is just --model wills-v1.mlmodel vs --model oe-v1.mlmodel; triage picks
  • • Evidence from our tests: CATMuS read the charter's Latin at usable quality while hallucinating the same page's OE bounds
